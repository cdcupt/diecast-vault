★ At a glance

The product loop, the architecture spine, and the load-bearing technical decisions in one frame. The iOS client does all capture, viewing, and personal storage on-device; a deliberately thin REST API on the shared BWH VPS brokers only identity, catalog, dedup keys, provenance, and presigned R2 URLs — model bytes never transit the VPS.

1 Infrastructure design

The server is deliberately thin: it brokers identity, catalog metadata, dedup keys, provenance, presigned R2 URLs, and the Real-Car enrichment cache. The single most important architectural line is the device-only vs server boundary — the personal shelf is a pure client↔CloudKit concern the backend is never told about; only opt-in community shares reach the VPS.

1.1 System & deployment

1.2 R2 key scheme

One bucket, prefix-partitioned and content-addressed so identical bytes are written once and the dedup key is self-documenting in the path. The client never sees R2 keys or secrets — presigning is server-side only with R2 S3-compatible credentials held in the server env.

2 Data model & entity relationships

Postgres stores metadata, keys, and provenance only — no blobs, no file paths to local disk. The device-only OwnedCopy is intentionally absent from the server. Diecast Vault runs its own dedicated diecast-postgres container, isolated from 9relay-postgres — BillMind-style deploy, but with separate data.

Scope boundary (load-bearing): device-only = OwnedCopy, personal USDZ/posters, acquiredAt/notes/wishlist, active locale, settings — never sent to the API. Server = Release, RealCarProfile, CommunityScan, Model, ModelUpload, User, TakedownReport. Personal models never auto-upload; only explicit, revocable, per-model opt-in shares reach the VPS.

3 Backend / API

Base: https://api.diecast-vault.<domain>/v1. Reconciled envelope: { success, data, error, meta } (chosen over ok per the contract — Risk R1). Bearer session JWT on writes/personalized reads; catalog + realcar GETs are public-cacheable with ETag/Cache-Control. Blob bytes never traverse the API — it only brokers presigned R2 URLs + metadata.

4 Frontend / iOS architecture

SwiftUI, iOS 17 minimum (pick/view), iOS 18+ for RealityView in the viewer. A 4-tab shell (Cabinet · Catalog · Library · Settings) preceded by a one-time capability gate. A TravelBilling-style pure DiecastVaultCore SwiftPM package holds the value-typed domain + the (mgtNumber, drive) key logic — but, unlike TravelBilling, it is linked as a real SPM dependency (no local-copy drift).

5.2 Capability gating

Gating is on the runtime API (ObjectCaptureSession.isSupported), never on device-name strings. The non-Pro path is the anti-template guarantee: scan affordances are informational steel notes with the same VoiceOver dignity as actions, never “disabled, dimmed” announcements that read as failure. App Store metadata correctly states the scan-capable devices.

6 QA test plan

Test priorities follow the locked architecture: pick-first on any iPhone (P0), Pro-only scan/contribute, opt-in community, Real-Car enrichment, EN + 简体中文, DMCA/IP guardrails. Two gating spikes run first, before any v1 build commitment (carried at Gate 1); each has a documented fallback and neither blocks the app.

6.1 Go/no-go spikes (run first)

Spike-0Scan quality on glossy/cased diecast

Proves: can Apple Object Capture on a LiDAR Pro iPhone produce a 1:64 Mini GT USDZ “good enough to show a friend”? Worst case for photogrammetry — small, glossy, specular, clear case, thin spoilers/wheels.

Inputs: 3–5 cars across a difficulty spread (gloss solid, large glass, fine thin parts, matte control), removed from case, diffuse light, using the Guided Capture sample / USDZScanner as-is.

GO livery + form read correctly at niche and viewer scale for ≥ 3 of 5 without re-scan, rest recovered by re-scan; reconstruct completes on-device without crashing.

NO-GO consistent failures even after re-scan → re-plan around community-pick + a seeded library; scan ships with an honest caveat or is deferred.

Judge: PM (owns the real collection) is final arbiter on the subjective bar; QA records objective telemetry (coverage, time, failure codes, re-scan count); two beta-testers give a secondary read. Recorded in the Gate-1 packet.

Spike-13D cabinet render + performance

Proves: does the real-time RealityKit cabinet (one mesh; hero = full USDZ, others = billboard/low-LOD; clamped orbit + gyro) hold frame + thermal budget at ~12–24 cars on target devices?

Procedure: populate 12 → 18 → 24 cars; exercise auto-orbit, clamp bounds, gyro parallax, hero promotion/demotion, lift-to-viewer, and the four style themes.

GO sustained 60 fps on baseline Pro; never < 30 fps on lowest device during promotion; thermalState never .serious/.critical in 5 min; bounded memory (demote releases USDZ), no jetsam; style swap = no geometry/data change.

NO-GO fails budget/thermals → fall back to the documented pseudo-3D flat-preview Home. Design degrades gracefully; never blocks.

Judge: QA on objective fps/memory/thermal (Instruments attached); PM confirms the look holds. Reduced-Motion variant verified (camera pinned, lit scene still renders). Recorded in the Gate-1 packet.

6.3 Test-type coverage

Unit (≥ 80%, pure logic, AAA)

Dedup key (mgtNumber, drive) — same no.+diff drive = two keys; same no.+same drive = collision; edition serial is per-copy, not in key; normalization round-trips. Catalog parse + versioned merge (skips malformed, consumes removed[]). Locale cache keying (en/zh-Hans separate; images shared; names stay proper nouns; unknown→en). Bonding validation (drive mandatory; serial optional; independent of scan). Lit-count semantics (owned only); origin enum; ~25 MB cap pre-check.

Integration (staging tenant)

Presigned R2 round-trip: download bytes bypass VPS, sha256 matches; upload → metadata-only in Postgres; expired/forged URL rejected; cap enforced both sides; dedup routes 2nd upload to “contribute alternative”. Auth (Apple sub → user, expiry/refresh/revoke). Enrichment (Wikidata/Wikipedia/Commons; cited history; AI fallback badged; cache hit no re-spend; official OpenAI not 9relay; no-match graceful). Takedown (report → flag → rapid-delist; repeat-infringer; revoke). VPS tenancy (own dedicated Postgres + port + vhost; docker restart caddy; co-tenants unaffected). iCloud two-device no-loss; zero VPS calls on local save.

E2E critical flows (deterministic waits)

  1. Pick → view → AR (any iPhone, P0): search → select drive (up front) → detail + provenance → Pick → light-on bloom → lift-from-case into dark stage → rotate/pinch → one-tap AR. Target under ~2 min first-time; “show a friend” is one tap.
  2. Scan → bond → share (Pro): remove-from-case → orbit w/ coverage → reconstruct (determinate) → verdict card (re-scan loop) → bond (number+drive+serial) → shelf tagged YOURS → post-scan share → consent+license+attestation → dedup → presigned PUT → Library tagged COMMUNITY + BY-YOU +1. Verify “Not now” keeps it private, no nag.
  3. Gap-nudge → scan (Pro): matte recess → tungsten CTA → scan flow. Non-Pro = calm steel note.
  4. Language switch incl. AI history: EN ↔ 简体中文 live, no relaunch; tabs read 陈列柜/目录/社区库/我的; Real-Car flips to matching cached profile (Songti SC); model name stays proper noun; documented light-relaunch fallback rather than mixed-locale strings.
  5. Offline cached: cached shelf fully works (cabinet, rotate, AR for cached); Library dims with steel note; Real-Car shows last-cached; never blacks out; picks not promised to queue in v1.

6.6 The two-beta-tester pass (gates Gate 3)

Mandatory before final review/ship. Two independent beta-testers exercise all five E2E flows on different device classes (ideally one Pro, one non-Pro) and both languages. They confirm: pick→view→AR feels finished and is one-tap to show a friend; the not-supported path reads as invitation, never failure; Spike-0 scan output (if scan ships) is “good enough to show a friend”; the language switch is clean (no mixed-locale strings); offline never blacks out. Both must sign “ship” before Gate 3; if either withholds, blocking issues are fixed and the beta pass re-runs after every substantial round of PM-requested fixes (trivial mechanical fixes need Coordinator review + verify only). 7.1 Deploy & CI

server

Thin tenant on shared BWH (BillMind-style)

Own dedicated diecast-postgres container (isolated from 9relay-postgres) in Diecast Vault's own compose project. Own localhost port (e.g. 127.0.0.1:8110, confirm free vs 9relay/BillMind:8099/scenario:8101). Append a Caddy vhost for api.diecast-vault.<domain> → docker restart 9relay-caddy (NOT reload — stale-inode bind mount). Resource caps (mem_limit, cpus). Unique names (diecast-vault-api), own compose project + deploy.env.

build

Off-box GHA → GHCR

If Swift (to share Core-style models), build via GitHub Actions on swift:6.2 → push to GHCR; the box pulls & runs (the BillMind pattern — the budget VPS doesn’t compile Swift). Go/Node images build in GHA either way. Deploy = docker compose pull && up -d from /opt/diecast-vault/app. Secrets in ~/.diecast-vault/deploy.env (chmod 600): DATABASE_URL, R2 creds, Apple keys, SESSION_JWT_SECRET, official OPENAI_API_KEY, IP_HASH_SALT — never in repo/memory/chat. Health → Gatus at status.daichenlab.com.

Build env: this Mac builds/runs iOS via the DEVELOPER_DIR override + xcodegen + iPhone 17 Pro simulator. Add Swift code to existing files where practical (avoid Xcode target-membership churn). Pure domain → DiecastVaultCore, tested via swift test (no simulator). Hooks order if wired: format → lint → type-check (--incremental + timeout) → build verification.

7.2 Phasing seam

v1 = local-first core loop (scan→bond→view→Real-Car) needing only /auth/*, /catalog/*, /realcar/*, /healthz. The community library + full upload/dedup/DMCA machinery (/community/*, /me/contributions, /reports, /dmca/notice) lands in v1.1 — but the schema, R2 layout, and API are designed now so v1.1 is purely additive (no migration churn). The DMCA designated-agent registration is the hard gate on enabling any /community/* write.

7.3 Launch-blocker checklist

  • Register the §512(c) DMCA Designated Agent with the U.S. Copyright Office ($6, renew every 3 yrs) — missing this alone forfeits safe harbor. Gates any community write.
  • Publish the designated-agent contact in-app (Settings, static content) before the community feature ships.
  • Notice-and-takedown flow live (/reports + /dmca/notice); a facially valid notice flags + rapidly delists the slot (TAKEDOWN_LOCKED).
  • Repeat-infringer policy enforced (strike_count → suspend at threshold; logged).
  • No car-maker / “Mini GT” trademark in app name, icon, or marketing; catalog number is descriptive metadata only.
  • View-only — no mesh/USDZ export, no print path in v1 (removes the most-litigated harm).
  • Real-car attribution shown per photo (CC-BY/BY-SA · Wikimedia Commons) + Source: Wikipedia on history; AI images badged “Illustration”, never passed off as real.
  • Spike-0 + Spike-1 verdicts recorded in the Gate-1 packet (each with its documented fallback) before committing the v1 Home/Scan build.
  • Both beta-testers sign “ship” before Gate 3.
  • VPS deploy coexists with 9relay + BillMind (own dedicated Postgres + port + vhost; caddy restarted; co-tenant health smoke-checked).
